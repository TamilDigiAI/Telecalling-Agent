## Stack and architecture

- Use Next.js, TypeScript and Tailwind for the CRM. Use Supabase Auth and Postgres for users, workspace membership, leads, calls, follow-up tasks and operational data. Build the telephony and voice runtime as a separate Node.js/TypeScript service that supports public HTTPS callbacks and long-lived WSS. Target Cloud Run for the voice runtime. Use a durable Postgres job table and a scheduled dispatcher, with atomic job claims, expiring leases and a reconciliation path for unknown provider outcomes. A cron tick or a web request alone must not own job state.
- Use Google Sheets API as lead intake and write-back. Use Exotel AgentStream for India telephony, Sarvam streaming speech recognition and TTS as the first Tanglish speech candidate, and an interchangeable text LLM adapter for dialogue and structured outcomes. Use mock adapters for all three providers. Implement adapters against their official protocols, including authentication, payloads, audio formats, callbacks, timeouts and provider error handling.
- Keep customer-facing sales calls and authenticated founder assistant in separate sessions with separate instructions and tool allowlists. Treat Sheet values, transcripts, notes and caller speech as untrusted data. A lead conversation can propose an outcome, request its own callback task, or opt itself out. Server tools enforce the active attempt, eligible contact, workspace, allowed callback slots and idempotency on these writes.
- Store timestamps in UTC and display and interpret founder requests in `Asia/Kolkata`. Use migrations, seeded mock data, typed config validation and a placeholder-only `.env.example`. Keep billing, self-serve provider onboarding and WhatsApp out of this first release.

## Workflow 1 · Qualify Google Sheet leads by phone

1. Connect one existing spreadsheet and tab with configurable header mappings. Import only leads eligible for the approved enquiry follow-up use case, with a valid phone, source, auditable calling permission or eligibility reference and an available time window. Keep the raw phone field as text and normalize valid Indian numbers to E.164. Show invalid, ineligible, or duplicate rows with reasons. Use a stable source lead ID or an automation-assigned UUID in row metadata for legacy rows and map it to the CRM lead. Suppress duplicate active calls across repeated imports, matching normalized numbers within the workspace and campaign while preserving source enquiry history. Respect existing suppression and new opt-outs before every dispatch.
2. Dial with the provider-approved caller ID and route. Use Exotel's direct Connect Voice AI only when the provider approves it for this use case and no required flow steps are missing. If the provider requires an applet, routing or compliance step, use the approved flow adapter and keep live mode blocked until it is configured. Configure authenticated HTTPS call-status callbacks and a protected bidirectional WSS media endpoint. Use documented provider authentication where supported. If status callbacks lack a documented signature, require a short-lived, high-entropy, per-attempt callback token and reconcile terminal outcomes against the authenticated provider API before treating them as final. Bind callbacks and streams to their call attempt, redact tokens, deduplicate repeated events and accept out-of-order delivery without regressing terminal status.
3. Handle telephony PCM, STT/TTS sample-rate and framing conversion, speech turn-taking, interruptions that stop queued audio, silence, busy, failed calls, and no answer. Use provider-supported voicemail detection when available, otherwise use review or a normal terminal call result without qualifying the lead. Keep call recording and persisted full transcripts off for the pilot. Persist only the minimum structured evidence and summary needed for follow-up. Confirm names, dates, times and numbers where mishearing changes an action.
4. Validate structured output and apply server-side qualification rules. Record `lead_temperature` as `HOT`, `WARM`, `COLD`, or `UNQUALIFIED`. Separately store `call_outcome` such as `CONNECTED`, `CALLBACK_REQUESTED`, `NO_ANSWER`, `BUSY`, `FAILED`, `VOICEMAIL`, `WRONG_NUMBER`, or `DO_NOT_CALL`.
   - **HOT** requires a current need and an agreed concrete next step, such as a demo, quote discussion or confirmed founder callback about that need.
   - **WARM** means relevant interest with an undecided timeline or a next step that is still unconfirmed.
   - **COLD** requires a conversation with explicit lack of interest or a clear mismatch. An opt-out sets `DO_NOT_CALL` and suppression independently of temperature.
   - **UNQUALIFIED** covers no usable conversation or insufficient evidence. A busy lead who only asks to be called later stays unqualified. An unanswered retry never downgrades a prior qualified result. Show manual review when evidence is unclear.
5. The model proposes `temperature`, `reason`, `need`, `timeline`, `budget_band`, `next_action`, `callback_at`, `opt_out` and a short summary using a schema with nullable unknowns. The server validates the evidence, booked actions and contact state. On verbal confirmation, the call-scoped callback tool saves one founder task with the agreed time. Upsert that same task in the final outcome transaction if it already exists. Describe the action as a founder callback, and reserve meeting confirmations for a verified booking. A do-not-call request is saved immediately, closes future calling tasks and cancels queued dial jobs before any Sheet sync. Store each attempt separately and respect a configured attempt cap, permitted hours and cooldown. If dispatch may have succeeded despite a network failure, reconcile it or surface it for review before dialing again.
6. Commit the outcome, qualification, task changes and an outbox record atomically in Postgres. Then update the same Google Sheet tab and lead row in automation-owned columns only. Use stable source identity and row-bound developer metadata or an equivalently safe write path. Validate the matched lead ID immediately before writing. Pause and surface ambiguous, deleted or remapped rows. Cover row moves, sorting and unrelated-column preservation in tests. Use RAW writes so a transcript fragment or note cannot become a formula. Make write-back idempotent, ordered per lead and independently retryable with a visible retry button. A Sheet failure never triggers a second phone call. Display a last successful sync timestamp and a clear failure state.

### Sales agent instructions

You are DigiAnchorZ's AI enquiry assistant. Use natural Tamil Nadu Tanglish, short spoken turns and one question at a time. Use Tamil script with familiar English sales words where that produces better speech and tune real call samples with local Tamil speakers. Follow a consultative NEPQ-style sequence: understand the current situation, ask what is causing the problem, explore the impact only when relevant, confirm priority and then ask permission for one practical next step. Follow what the lead says instead of reading a fixed script. Switch to Tamil or English when requested. Confirm the call is for the intended person before sharing their enquiry details. Explain the call purpose, respect a decline, and offer a founder follow-up if useful. Use the approved knowledge base for facts, availability and prices. Ask for clarification when unclear and avoid inventing answers or commitments. Never pressure the lead or ask for passwords, OTPs or bank details.

Example opening: “Vanakkam, naan DigiAnchorZ-oda AI enquiry assistant pesuren. [Name] kitta dhaan pesurena?” After confirmation: “Neenga [service] pathi enquiry pannirundheenga. Ippo rendu nimisham pesalaama?”

Sample questions to adapt:
- “Ippo indha work-a eppadi handle pannittu irukkeenga?”
- “Adhula ungalukku biggest challenge enna?”
- “Idhu unga enquiries-a illa sales-a eppadi affect pannudhu?”
- “Idha eppo start panna plan panreenga?”
- “Namma founder kooda oru short call arrange pannalaama? Ungalukku endha time convenient?”

If the lead says “inimel call panna vendaam,” acknowledge once, invoke the opt-out action and end politely. For a callback, repeat the exact local date and time. Describe it as booked only after the task tool returns success.
